# 构建与验收脚本规则

- 先读源码CODEX及当前状态；按真实调用链判定脚本是否写文件、启动HTTP、访问私有存储或云端，不能只凭audit/test/preview命名判安全。
- build-sites会删除并重建dist，必须在明确归属的新候选中执行，不覆盖冻结A39或当前CMS选择。
- 使用既有parse5/acorn/css-tree和Node标准库；保持原CSS/JS顺序、canonical/别名/真实301/404/HEAD/405。
- 最后生成完整SHA256资源身份/SRI及有限immutable路径；未知CSS/JS依赖需明确构建规则，不能静默拷贝后失效。
- server/cms/var/SQLite/凭据/客户图稿/发布审核证据不得进公开产物；注意现有白名单会复制部署说明与content目录公开部分。
- 质量门槛保持真实范围：preflight:aliyun前后审查，preview也含完整quality。Docker/私有执行延期时不得直接跑全链。
- 历史受限控制器不可原样重跑固定目录；新验证设独立输出、进程期限、空间门槛和清理归属，保留错误证据。
- 用户已明确授权的Git/阿里云版本同步可执行；操作前固定版本与作用域。不得擅自扩大到DNS、删除远端对象或绕过内容审核；未知写入结果先确认同一操作身份。
