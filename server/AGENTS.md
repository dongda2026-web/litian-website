# Private Inquiry Service Rules

- Keep this directory outside dist/client and public OSS. Serve admin assets only through the explicit route allowlist; all customer read/write APIs require authentication.
- Node >=22.18; Node 22.23.0 is the tested runtime. SQLite is experimental in Node 22 and requires a single instance with a private durable volume. Pin and test runtime upgrades.
- Never embed INQUIRY_ADMIN_TOKEN, session cookies, webhook secrets or customer data in HTML, logs, icons, public content, screenshots or source snapshots. Screenshots and browser fixtures use synthetic records only.
- Production cookies are HttpOnly, SameSite=Strict and Secure with absolute 30-minute expiry. Require exact Origin and CSRF token for browser writes. Do not enable localPreview in the production entrypoint or replace bearer/session checks with CORS checks.
- No browser localStorage/sessionStorage for administrator credentials or customer records. Render untrusted fields with textContent. Preserve DOM hook classes when changing feedback styles.
- Preserve unsaved drafts on failures and notification retries. Stale followups return 409; never silently overwrite another browser's update. Server-to-server integrations should also supply expectedRevision.
- Migrations must be additive and must retain inquiries/outbox/history. Use a SQLite-safe private backup before schema changes. Application rollback must never delete or replace live customer data.
- Use prepared statements and validated filter enums. Keyset pagination uses both received_at and id; test tied timestamps. Keep list queries bounded; avoid one query per result.
- Gateway accepted is not inbox delivered. Preserve failures, deduplicate notification requests, and keep a pending state when a real gateway/recipient is missing.
- CRM synchronization is independent of notification delivery. Only a strict matching persisted main-system ACK may set synced. Preserve original payload, DD identity, endpoint binding and leases across retries. Never reuse an admin/staff token or allow browser tenant/owner injection.
- Once CRM is configured, local follow-up writes are disabled. Main-system staff permissions/assignment/CAS remain the authoritative workflow; synced data cannot become editable merely because configuration is removed.
- Run npm test and preflight:aliyun. Tests include admin/browser JS syntax checking, real HTTP permissions/CSRF/logout, migrations, optimistic revision conflict and notifications. Browser acceptance must cover phone/tablet/desktop plus retry/error/draft behavior. SSO/individual staff roles and actual provider delivery remain explicit release gaps until verified.
- A9 monitoring is private aggregate-only. True intake totals come from committed inquiries, not clicks/HTTP retries. Gateway acceptance is not inbox delivery; ERP saved requires its existing strict ACK. Local stage progression is not customer reply or ERP followup readback.
- Before the A9 additive migration, VACUUM INTO creates a private 0600 backup under a 0700 backups directory, validates integrity and flushes file/directory. Failure stops startup before migration. Never replace current data with that backup during application rollback.
- Daily HTTP/delivery counters keep bounded enums and 90 UTC calendar days (hourly lazy pruning). Never record addresses, URL/query/referrer/UTM, bodies, error messages, company/contact/receipt/ERP IDs or credentials. No visitor tracking or attribution is enabled by A9.
- Delivery state and its daily outcome counter commit atomically behind a matching lease token. Best-effort HTTP/worker counters must not invalidate committed inquiries; capture failures are reported privately. A recent worker poll is not successful delivery or a production uptime guarantee.
- A10 sample-request uses sample-only ERP v3 with the existing 16 KiB actual-byte limit; v2/64 KiB remains RFQ-only. Validate canonical product, strict recipient/demand fields and explicit cost acknowledgement before commit. Do not project sample units or expected purchase volume to generic order quantity.
- Sample review lives only in the main system's employee endpoint with organization/owner/write/CAS checks. Original sample demand is immutable; delivery ACK is neither review nor shipment. Keep recipient data out of aggregate monitoring, browser storage and public receipt readback.
- A11 uses v4 only for quote-root or RFQ-line customization. Shared exact-key validation keeps explicit units, positive decimal dimensions/load and bounded printing requests; quote remains 16 KiB, RFQ 64 KiB streamed bytes. Preserve v1/v2/v3 and all existing digest/assignment/receipt/lease protections.
- Customization is original private buyer demand, not certified product data or technical approval. Retain it in the durable payload/ERP source metadata and read-only employee UI, never public receipts, aggregates, browser caches or mailto fallback. No attachment upload is implemented by this batch.
- A12 is an unfinished private-upload candidate, not an enabled form or an ERP release. Uploaded IDs require server resolution within the owning short-lived session; browser metadata is never canonical. Bind bytes/metadata and inquiry in the same SQLite transaction, retain original hashes and immutable policy identities. Expiry during parsing/scanning must also reject, including same-key retries.
- Default uploads remain disabled. Attached CRM requests must block until real ERP byte transport and organization/owner-aware reads pass acceptance; non-attachment contracts stay compatible. Never drop attachments to manufacture a successful v4 ACK.
- Apply the local scanner/PDF rules in upload-scanner/README.md. Mock scanner tests, real standard antivirus detection and independent PDF structural rejection are different evidence. Resource/decoding/CDR and production retention/backup/scale remain gates; never treat a clean scan or source preflight as public-upload readiness.
- A12 v5 transport is locally accepted only with explicit trusted-server crmAttachmentsEnabled=true. Resolve original metadata/bytes from the bound SQLite record and verify every exact id/hash in the persisted ERP ACK; no legacy ACK or dropped-file success. Default still blocks. Public upload UI and production entrypoint activation remain pending.
- ERP private originals reuse immutable archive storage and current sales org/owner checks. Generic archive/sync exclusion guards must survive feature rollback; disabling a worker never authorizes exposing retained originals. Binary-first then sales-transaction is recoverable partial persistence, not a distributed atomic commit. Preserve failures/originals/identity and use existing authorized queue retry after acceptance.
- Transport evidence: outputs/upgrade-logs/2026-10-08-private-attachments-erp (120 website, 61 sales, 69 archive/sync, 3 local PG groups, real ClamAV and new-process HTTP readback). Do not claim employee/public UI, production PG, deployment or full A12/C02 completion from these results.
- A12 image integration changes the private-upload source candidate, invalidating prior website upload/HTTP regression results for this source. ImageUploadInspector uses only a private Unix socket; readiness decodes a fixed image. A required inspector must reject absence/failure before issuing a new capability or persisting new image bytes.
- image_policy/image_inspection are private additive provenance columns, not fields added to the v5 canonical ERP envelope. New rows require pinned proof matching immutable original bytes; legacy bound rows remain legacy without relabeling. Old unchecked ready images cannot newly bind. Back up using the existing pre-a12 helper before migration. Never restore old business data or enable public uploads on rollback.
- Current local evidence: 30/30 Node adapter/private-upload groups and 132/132 website tests passed; the old broker image also passed real isolated image/AV/SQLite/HTTP acceptance. The full preflight stopped at an incomplete test-fixture build closure, not a passing release gate. A minimal runtime is built locally, and the changed broker has 14/14 groups; real HTTP on that final image and ERP regression still need execution. Docker's Linux environment stopped during ERP tooling preparation. Do not replace it with unsandboxed tests or claim deployment. New evidence: outputs/upgrade-logs/2026-10-08-image-upload-acceptance; prior checkpoints remain frozen.
- Keep public entrypoints, previews and cloud/domain/finance routes unchanged. Minimal-runtime supply-chain/production-capacity approval, CDR/PDF whole-process isolation, retention and full final preflight remain open. Cooperating services must use a dedicated, explicitly budgeted UID; never mount unrelated business data or discard original bytes to recover from resource failures.
