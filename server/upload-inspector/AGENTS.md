# Private Image Inspection Rules

- Stdin-only, single-job candidate, never public/static code. Use Pillow for actual decoding, not a custom decoder. Envelope checks reject unsupported framing/trailing data without changing original bytes.
- Require exact approved MIME, static PNG/JPEG, fixed byte/pixel/segment limits, verify plus full load, fixed errors and original hash. Never return input filenames, metadata text, bytes or parser exceptions.
- Linux resource limits are defense in depth, not a network/filesystem sandbox. Run only under an unprivileged dedicated OS supervisor/container with no external network, read-only source/root, scratch-only writable mount, no host credentials/data/socket access, bounded memory/PIDs/CPU/disk and a parent wall deadline. Do not execute uploaded content or create derivatives.
- Local acceptance may reuse the existing Pillow toolchain image but must not adopt that unrelated application image as production architecture. Pin/review a separate minimal image and library/runtime versions before release.
- The broker/client is wired into the private-uploads.mjs SOURCE CANDIDATE only. Linux Node adapter/transaction 30/30 and the prior broker image's real private-upload HTTP chain passed locally. Full preflight, new-image HTTP/ERP regression and production readiness remain pending. Public/default entrypoints remain off; never promote from Python tests alone.
- Persist image_policy and image_inspection separately from the existing v5 validationPolicy. Never silently upgrade or relabel old originals. Legacy bound originals retain exact metadata/readback/retry identity; unchecked ready images cannot newly bind. Deleting proof for a new-policy image must fail closed.
- Tests use synthetic bytes and a selected public JPEG only. Source mounts are read-only; no runtime secrets, customer files, databases or Docker socket may be mounted. Keep tests bounded and preserve failures. Passing decode or clean AV does not certify harmlessness/CDR/technical approval.
- Linux RLIMIT_NPROC counts the shared numeric UID across services, not only this broker. Use a dedicated UID, account for API/scanner/test-runner threads, and replace a preparation runner with exec instead of retaining an extra Node parent. Preserve the container PID and worker limits. Failed thread creation must close the connection, release its acquired slot and never join an unstarted thread. Production service-capacity review is still required.
